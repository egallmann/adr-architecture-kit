# Private AI 1.5 source-backed semantic fields

`semantic_fields::{execute, verify}` consumes only the existing private
`identity_representation::SealedSources`, exact candidate bundles and selections.
The witness can only originate in the native-source sealer. Each operation
requalifies the current NM/AI/ACC definitions and replays original bytes, source
schemas, canonical identities, minimal source roots and detached context.
No caller assertion or prior success status establishes qualification.

The producer reuses the AI 1.3 field-disposition engine. Its historical ACC 1.3
entry point keeps its original execution restrictions. The native entry point
uses the same catalog, destination validation and field-coverage mechanisms,
with the proposition schema branch and schema-discovered child membership.
There is no second semantic mapping table or version-adapted receipt.

The verifier does not call the semantic producer or field-projection function.
It enumerates the original authored fields, resolves each actual disposition,
checks the full proof record, reads the declared output destination, and checks
exact source values. Unordered multiset outputs are compared with occurrence
multiplicity; ordered child membership retains authored order. Source values in
coverage records retain their original typed JSON independently of the output
comparison. Child payload in a coverage record is preservation evidence; the
parent's membership value contains only child UUIDs, never child-owned payload.
Optional absence differs from an authored empty value. Omitted or additional
placements, extensions, coverage records and units fail atomically.

Native declaring ownership comes from exact qualified source containment and
the inherited AI 1.3 ownership row: schema path, child schema, declaring UUID,
status selector and literal status. No composition is performed or inferred.
The carrier retains its actual AI 1.3 rule resource/digest/SCF under enclosing
AI 1.5 selection. It is schema-validated and independently rederived during
verification. `context/declaring_adr_lifecycle#` binds the child UUID to that
carrier; the lifecycle value occurs once at `/lifecycle_stage`. Propositions
receive neither the carrier nor lifecycle. Locators and digests are integrity
information, never owner identity.

Identity representations remain a separate proof: the existing three recipe
implementations are unchanged, and the existing independent identity verifier
checks the representation evidence embedded in this private result. No derived
representation is admitted as an authored semantic field.

## Executed surface and remaining scope

The actual AI 1.5 catalog contains 27 types in six branches. Catalog qualification
is not instance execution or independent-root permission. The focused Rust tests
execute native `adr/logical`, embedded `entity/decision`, embedded
`entity/normative_proposition`, and embedded `entity/boundary`. The regular
boundary uses the same field and ownership mechanics; these examples are not a
new normative type catalog or a permanent execution limit.

| Current catalog branch | Qualification and instance boundary |
| --- | --- |
| regular (17 types) | Logical ADR, Decision and Boundary execute in focused fixtures. Other regular rules remain catalog-qualified; their actual fields and source/context prerequisites must qualify before execution. System shared identity and custom Extension CEC/lifecycle qualification are Unavailable. |
| normative-proposition (1 type) | Embedded proposition fields execute, lifecycle-free. Standalone context remains Unavailable. |
| canonical-relationship (1 type) | Rule authority is qualified; relationship qualification and record execution remain Unavailable. |
| compatibility-relationship (6 types) | No fabricated endpoint resolution or compatibility tuple. Execution remains Unavailable. |
| proposition-owned-value (1 type) | Normative force executes once through its proposition field disposition, with no second unit. Independent value-root execution is Unavailable. |
| owner-local-value (1 type) | No fabricated roots/owners. Exact owning-unit/value execution remains a separate prerequisite. |

The branch names and counts are derived from the current catalog; no alternate
catalog is introduced. The five disposition classes are retained. Executed fixtures use
canonical placement, direct semantic value and deterministic ceremony. No
published declared-absence field is encountered. Compatibility projection and
any unsupported disposition prerequisite fail closed; they are not replaced by
fallback values or a sixth class.

Selecting a parent requires selection and successful field projection of every
discovered child semantic unit. Standalone regular fragments without qualified
declaring lifecycle remain native artifacts with Unavailable interpretation.
Shared identities, custom qualification, relationship endpoints and owner-local
context cannot be invented to make a result appear complete.

`Executed` and `Verified` describe bounded private facts. Complete interpretation
is always `Unavailable`. Known invalidity is `Rejected`; missing prerequisites
are `Unavailable`. No governed unresolved-dependency evidence is accepted by this
seam, so it cannot manufacture `Unresolved`. Diagnostics retain independent
violations; failed qualification releases no units, representation, authority or
basis evidence. This is neither full NM schema validation nor whole-ledger
semantic equivalence.

All 215 static BLOCKED outputs remain unchanged. Missing fingerprint, source
and completeness recipes, broader branch execution, full NM entity/model
validation, and independent expected/observed ledgers remain prerequisites to
complete execution. Public dispatch, SDKs, SCS, capabilities and promotion remain
unchanged. Cargo's existing full test gate discovers the private module's tests.
