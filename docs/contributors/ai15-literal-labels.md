# Private AI 1.5 literal label representations

`semantic_fields::labels::{qualify_catalog, execute, verify}` is a private Rust
boundary. Its input is the existing exact candidate bundles, native sealed
sources and source selections. No protocol, SDK, capability or SCS registration
is added. The existing full Cargo test gate discovers its focused tests.

The catalog, not a Rust mapping table, selects the label definitions. Static
qualification enumerates the actual `literal_string_copy` producers, checks the
closed companion schema, unique destination and rule, exact required authored
property and string schema, original field disposition, output branch and exact
NM destination schema fragment. The actual inherited AI 1.4 `/operation` binding
retains its resource identity and digest under enclosing AI 1.5 selection.
Candidate qualification remains revision-sensitive without a permanent SCF pin.

Execution independently replays the native source witness, established UUID,
selected provider context and current candidate closure through the existing
semantic-field and identity boundaries. It copies the original JSON string
exactly. The complete value is validated against its qualified source and NM
output fragments. This does not validate or assemble an entire normalized entity.
No trimming, normalization, fallback, truncation or synthetic label is admitted.

Labels are a separate representation sidecar. The original semantic-field proof
and identity representations remain intact and independently verified. A label
cannot compete with an authored placement or become another semantic owner.
In particular, copying context, description, statement or other substantive text
does not remove its semantic extension or original canonical placement.

The inverse verifier does not call either label or semantic-field producer. It
replays original sealed evidence, resolves the actual rule and required input,
compares the full label bytes, validates the exact destination fragment, and
checks the original semantic-field proof with its independent inverse verifier.
It rejects omissions, duplicate producers, changed selectors, stale authority,
changed source semantics and forged envelopes even when strings remain equal.

The fixtures exercise 20 distinct definitions across 14 types, spanning regular
and normative-proposition branches. The remaining six are statically qualified,
not claimed executed. Catalog membership does not authorize an independent root.
All nine relationship/value types remain outside these entity label recipes.
There is no new hardcoded runtime type allowlist; other instances must establish
their complete existing source, identity, field and contextual prerequisites.

Known violations are Rejected; missing prerequisites are Unavailable. This seam
has no governed unresolved-dependency input and cannot manufacture Unresolved.
Failures clear all labels, semantic/source proof, authority and basis evidence,
while retaining deterministic diagnostics. Complete interpretation is always
Unavailable. Standalone regular fragments cannot obtain synthetic owners.
Propositions acquire no lifecycle or regular-entity status.

All 215 static BLOCKED destinations remain unchanged. Entity fingerprints,
source/completeness envelopes, broader branch/context execution, full entity and
model validation, and complete independent expected/observed ledgers remain
separate prerequisites. Label verification is not whole-ledger equality,
semantic_equivalent, Constructed, admission, promotion or publication.

Physical System fixtures independently execute Data Flow and System Boundary
summaries from their exact authored descriptions. The complete original
description remains at its canonical semantic destination. These operations do
not require unrelated root/System output to be executable. A requested atomic
scope including an unqualified System still withholds every output in that
operation. System name/summary and the full Physical System root projection
remain Unavailable under the current producer-evidence boundary.
