# Private AI 1.5 source-backed semantic fields

`semantic_fields::{execute, verify}` consumes only the existing private
`identity_representation::SealedSources`, exact candidate bundles and selections.
The witness can only originate in the native-source sealer. Each operation
requalifies the current NM/AI/ACC definitions and replays original bytes, source
schemas, canonical identities, minimal source roots and detached context.
No caller assertion or prior success status establishes qualification.

The producer reuses the AI 1.3 field-disposition engine. Its historical ACC 1.3
entry point keeps its original execution restrictions. The native entry point
uses the same catalog, destination validation and field-coverage mechanisms,
with the proposition schema branch and schema-discovered child membership.
There is no second semantic mapping table or version-adapted receipt.

The verifier does not call the semantic producer or field-projection function.
It enumerates the original authored fields, resolves each actual disposition,
checks the full proof record, reads the declared output destination, and checks
exact source values. Unordered multiset outputs are compared with occurrence
multiplicity; ordered child membership retains authored order. Source values in
coverage records retain their original typed JSON independently of the output
comparison. Child payload in a coverage record is preservation evidence; the
parent's membership value contains only child UUIDs, never child-owned payload.
Optional absence differs from an authored empty value. Omitted or additional
placements, extensions, coverage records and units fail atomically.

Native declaring ownership comes from exact qualified source containment and
the inherited AI 1.3 ownership row: schema path, child schema, declaring UUID,
status selector and literal status. No composition is performed or inferred.
The carrier retains its actual AI 1.3 rule resource/digest/SCF under enclosing
AI 1.5 selection. It is schema-validated and independently rederived during
verification. `context/declaring_adr_lifecycle#` binds the child UUID to that
carrier; the lifecycle value occurs once at `/lifecycle_stage`. Propositions
receive neither the carrier nor lifecycle. Locators and digests are integrity
information, never owner identity.

Identity representations remain a separate proof: the existing three recipe
implementations are unchanged, and the existing independent identity verifier
checks the representation evidence embedded in this private result. No derived
representation is admitted as an authored semantic field.

## Executed surface and remaining scope

The actual AI 1.5 catalog contains 27 types in six branches. Catalog qualification
is not instance execution or independent-root permission. The focused Rust tests
execute native `adr/logical`, embedded `entity/decision`, embedded
`entity/normative_proposition`, embedded `entity/boundary`, and physical-component
`entity/component` / nested `entity/interface` occurrences. The regular
boundary uses the same field and ownership mechanics; these examples are not a
new normative type catalog or a permanent execution limit.

| Current catalog branch | Qualification and instance boundary |
| --- | --- |
| regular (17 types) | Logical ADR, Decision, Boundary, Component and nested Interface execute in focused fixtures. Other regular rules remain catalog-qualified; their actual fields and source/context prerequisites must qualify before execution. System shared identity and custom Extension CEC/lifecycle qualification are Unavailable. |
| normative-proposition (1 type) | Embedded proposition fields execute, lifecycle-free. Standalone context remains Unavailable. |
| canonical-relationship (1 type) | Rule authority is qualified; relationship qualification and record execution remain Unavailable. |
| compatibility-relationship (6 types) | No fabricated endpoint resolution or compatibility tuple. Execution remains Unavailable. |
| proposition-owned-value (1 type) | Normative force executes once through its proposition field disposition, with no second unit. Independent value-root execution is Unavailable. |
| owner-local-value (1 type) | No fabricated roots/owners. Exact owning-unit/value execution remains a separate prerequisite. |

The branch names and counts are derived from the current catalog; no alternate
catalog is introduced. The five disposition classes are retained. Executed fixtures use
canonical placement, direct semantic value and deterministic ceremony. No
published declared-absence field is encountered. Compatibility projection and
any unsupported disposition prerequisite fail closed; they are not replaced by
fallback values or a sixth class.

Selecting a parent requires selection and successful field projection of every
discovered child semantic unit. Standalone regular fragments without qualified
declaring lifecycle remain native artifacts with Unavailable interpretation.
Shared identities, custom qualification, relationship endpoints and owner-local
context cannot be invented to make a result appear complete.

`Executed` and `Verified` describe bounded private facts. Complete interpretation
is always `Unavailable`. Known invalidity is `Rejected`; missing prerequisites
are `Unavailable`. No governed unresolved-dependency evidence is accepted by this
seam, so it cannot manufacture `Unresolved`. Diagnostics retain independent
violations; failed qualification releases no units, representation, authority or
basis evidence. This is neither full NM schema validation nor whole-ledger
semantic equivalence.

All 215 static BLOCKED outputs remain unchanged. Missing fingerprint, source
and completeness recipes, broader branch execution, full NM entity/model
validation, and independent expected/observed ledgers remain prerequisites to
complete execution. Public dispatch, SDKs, SCS, capabilities and promotion remain
unchanged. Cargo's existing full test gate discovers the private module's tests.

## Nested native Component and Interface evidence

The existing schema traversal retains the nearest semantic parent occurrence
separately from the declaring ADR. `identity_representation::native_ownership`
qualifies exact selected rule/resource references, source/parent/child schemas,
all three UUID selectors, original complete subtrees and both schema hops. This
bounded array-path checker supports the selected one/two-hop ownership rows;
arbitrary nesting is not lifecycle authority.

The executed rules retain their actual AI 1.3 identities:

- `declaring-lifecycle.adr-physical-component.component_specifications`
- `declaring-lifecycle.adr-physical-component.component_specifications.interfaces`

For `/component_specifications/*/interfaces/*`, the first schema hop is Physical
Component ADR `/properties/component_specifications/items` to common
`/definitions/component`; the second is common
`/definitions/component/properties/interfaces/items` to `/definitions/interface`.
Each edge must resolve the exact next schema key and pointer, not an equivalent
shape. The declared UUID comes from the ADR, the immediate parent UUID from the
Component, and the child UUID from the Interface. Locators select subtrees and
never replace those identities. Literal lifecycle comes only from ADR status.

A private containment witness accompanies each inherited lifecycle. It records
original declaring, parent and child occurrences/UUIDs and the selected rule.
The existing closed lifecycle carrier is unchanged and contains only its
governed declaring-ADR facts, without a second lifecycle value or invented
parent approval. Contextual facts stay bound to the child UUID. The witness is
integrity evidence, not another semantic field or registry.

Both execution and inverse verification rebuild occurrences from original
sealed bytes. The inverse checks the fresh witness and closed carrier, original
field values, membership UUIDs and multiplicity, identity representations and
literal labels. It never calls the field or label producers. Moving an Interface
to a different Component changes parent membership and the containment witness
even if the declaring ADR and lifecycle remain identical. A legitimate new
source revision can qualify freshly; an old or forged receipt cannot be rebound
to it by replacing only digests or success flags.

Focused fixtures exercise all 11 Component and seven Interface field
dispositions, including typed generation context, repeated reference values,
optional presence, and child membership. Authored Interface membership order is
retained as source evidence; its published `identity_keyed_set` classification
and duplicate-identity rejection remain unchanged. Interface payload remains
owned by its own UUID, outside the Component membership value. The existing label
engine additionally executes the three catalog-selected definitions: Component
summary and Interface name/summary. The full multi-document fixture contains four
Components and eight Interfaces under two independently qualified ADRs.

Selecting nested units does not require execution of unrelated root fields.
Selecting a Component still requires projection of all its discovered Interface
children. Native fragments with no qualified declaring ADR remain Unavailable;
known duplicate identities and contradictory source/ownership evidence are
Rejected. Failures clear containment, semantic and representation evidence
atomically. No unresolved-dependency evidence is invented. All 215 static
BLOCKED destinations and the complete-interpretation Unavailable boundary remain.

## Native Physical System evidence

The existing ownership qualifier also supports the selected single direct-object
hop. It validates `/system` against the Physical System schema
`/properties/system` and the common `/definitions/system` schema. It never
relabels the object as an array. The existing one/two-hop array paths and their
exact schema resolution remain unchanged.

The actual inherited AI 1.3 rules exercised are:

- `declaring-lifecycle.adr-physical-system.system` (containment evidence only)
- `declaring-lifecycle.adr-physical-system.data_flows`
- `declaring-lifecycle.adr-physical-system.system_boundaries`

Data Flow and System Boundary occurrences retain their independent UUIDs and
inherit literal status only from the declaring Physical System ADR. Their source,
parent and child schemas, schema-hop selectors, rule qualification and lifecycle
carrier are independently reconstructed. Focused fixtures execute all nine Data
Flow and seven System Boundary authored-field dispositions, including repeated
typed collection values. Ordered topology-key paths are retained as authored
semantic fields; this is not topology-record construction or endpoint resolution.
Boundary unordered-multiset classifications do not authorize dropping duplicates
or changing the retained original source values. No whole-ledger comparison is
claimed. The existing identity and literal-label inverses verify the sidecars.

Shared-System containment and semantic producer qualification are separate.
The selected reuse rule permits coincident declaring-ADR/descriptor source-role
UUIDs; that permission does not elect a System producer. The current native
handoff seals all retained bytes under the qualified detached provider, but does
not prove provider-wide source completeness or bind an independently established
existing System unit to a unique producer. Even one visible System claim therefore
remains Unavailable. Adding a local complete/preferred flag, identical aliases,
source order, file names or digest comparisons cannot supply that evidence.

All observed same-System-identity claims are accounted for when that producer
is requested. Conflicting values at governed canonical fields are Rejected;
equal repeated claims remain Unavailable. Distinct UUIDs stay distinct source
occurrences. No registry, coalescence algorithm, winner or new semantic unit is
manufactured. A partial basis cannot imply global uniqueness.

Unrequested shared-System claims do not block independent Data Flow/Boundary
facts. Selecting System atomically with siblings still clears the entire requested
operation on failure. Root identity-only facts can qualify independently when
their source roles are unambiguous; they are not proof of a System producer.
Full root field/label projection still needs its System child semantics and
therefore remains Unavailable at this seam. No complete Physical System entity
or model is assembled.

Inverse tests reject changed original fields, lifecycle, declaring/parent IDs,
containment selectors, receipts and labels without invoking the field or label
producer to reconstruct expected values. The precise System execution prerequisite
is independently qualified provider/source scope plus an established unique
System semantic-unit/producer binding under the selected authority. Other
unqualified contexts, all 215 static BLOCKED destinations and complete
interpretation remain unchanged and Unavailable.
