# AI 1.4 required-output authority qualification

The private `architecture_interpretation_v14` module qualifies static published
output authority. It does not receive construction requests, output values,
source instances, candidate records or caller assertions of applicability.

`qualify` accepts three supplied definition/resource bundles: exact AI 1.4,
ACC 1.4 and NM 2.5. Their published SCFs and full closures independently verify
through the shared semantic-contract implementation. Overlapping contents must
match, ACC must select the supplied AI definition, and the actual inherited AI
1.3 definition/closure is separately verified. Extra supplied resources confer
no authority. Production has no filesystem or ambient registry access.

The qualifier validates the closed required-output companion schema and checks:

- The catalog/type mapping/source selectors and identity policies agree with
  the actual inherited AI 1.3 resources.
- The six output branches select the matching NM discriminator/required-field
  branches. Full required/conditional schema inventories are independently
  traversed through sealed references; constraints remain attached to evidence.
- Required, conditional, authored semantic and nested destinations are accounted.
  A complete parent-value producer owns its nested fields once.
- Each destination has one declaration, with a qualified producer definition or
  an exact BLOCKED register entry. All seven published producer kinds are checked
  against their own inputs/rule identities and destination semantics.
- All 26 literal-copy rules agree with the exact frozen label oracles, required
  string source selectors and representation-only ownership. Original authored
  destinations remain independently significant. System summary is only its
  explicitly selected alias label; no narrative is inferred.

The private evidence retains selected authority definitions, per-type source and
branch selection, complete schema constraints, destination declarations, exact
producer references, blockers and deterministic findings. `verify` independently
replays qualification and compares the complete evidence. Evidence fields are
private and expose read-only views.

## Static authority is not instance completeness

Genuine catalog accounting is 27 semantic types, six branches, 186 qualified
producer definitions, 269 BLOCKED declarations and 14 blocker categories. Counts
are regression assertions after independent checks, never qualification inputs.
Catalog membership grants no independent-root permission.

Every destination has `Applicability::Unknown` because this seam accepts no
qualified instance facts. A static BLOCKED declaration is not a proven applicable
instance blocker; a qualified definition is not an instance producer. In particular,
conditional fields are neither automatically applicable nor presumed absent.
Proven inapplicability and missing instance prerequisites require a later qualified
instance seam. Complete interpretation always remains `Unavailable`.

Missing exact authority or unsupported schema capability is `Unavailable`;
independently established catalog violations are `Rejected`. Findings are sorted
and retained, with Rejected before Unavailable. This seam performs no governed
reference resolution and never manufactures an Unresolved finding.

## Schema and execution boundaries

The existing sealed evaluator preflights selected source/destination schemas and
complete catalog companions before validation. `semanticDependencies` is verified
as an integrity annotation and removed only from the evaluation view. Unsupported
constraints such as dependentRequired or unevaluatedProperties fail closed as
Unavailable. The requirement inventory retains condition schemas; it does not
pretend to evaluate them without an instance. No broad schema engine is added.

Source-field schema probes test string domains, including source-valid empty,
long and Unicode strings; they are not label execution or representation-instance
verification. Changed/generated/truncated label rules and forged evidence fail
qualification, but actual label output execution remains deferred. Frozen AI14
publication oracles are consumed as authority, not relabeled as complete runtime
conformance.

No NM 2.5 records, lifecycle carriers, source basis, ledgers or construction
outcomes are produced. Historical projectors/producers, protocol 1.5, WASM exports,
host APIs, capabilities, current SCS and immutable authorities are unchanged.

Next prerequisites are governed resolution of missing representation recipes and
context/custom/relationship/owner-local prerequisites, followed by a separately
bounded qualified-instance applicability/representation verifier and materializer.
