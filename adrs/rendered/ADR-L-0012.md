# ADR-L-0012: Federation Authority and Qualified Identity Model

**Status:** accepted  
**Created:** 2026-03-14

## Context

The current compiler and recursive multi-scope behavior preserve scope-local
compilation boundaries, but the STE ecosystem is moving toward federation
across independently compiled repositories. The planning material establishes
that federation must remain read-only, that each repository is authoritative
over its own entities, and that bare local IDs must evolve into an
unambiguous multi-repository identity model without breaking single-repo
authoring.

Those rules are architectural decisions, not temporary implementation notes.
They determine how repositories reference each other, how conflicts are
resolved, and what the federation layer is allowed to do with canonical
per-repo registries.

What is needed is one explicit ADR that formalizes:
1. Federation as a read-only aggregation step over independently compiled repos
2. Provider-authoritative conflict resolution for entity definitions
3. A qualified identity model with namespace separated from bare ID
4. Bare local references remaining valid by default, with qualification only
   when cross-repo references are intended


## Capabilities

### CAP-0038: Federated Qualified Identity Resolution

Support unambiguous multi-repository entity references using namespaces and
qualified identifiers while preserving bare local references in source ADRs.

### INV-0058

**Statement:** Federation and aggregation layers MUST treat each repository as

**Scope:** global

**Verification:** automated

**Rationale:**
Multi-repository architecture reasoning depends on repository ownership and
read-only aggregation remaining explicit.






## Decisions

### DEC-0045: Treat federation as a read-only aggregation layer over per-repo canonical registries

**Rationale:**
Per-repository registries remain the canonical architecture outputs for
their owning repository. Federation exists to read, index, merge, and query
across those outputs; it must not rewrite or mutate them.



**Consequences:**

**Positive:**
- Repository ownership boundaries remain explicit
- Federation can be added or evolved without changing local compiler output
- Global analysis stays traceable to per-repo canonical state



### DEC-0046: Use provider-authoritative conflict resolution for federated entity definitions

**Rationale:**
When one repository references an entity defined by another repository, the
defining repository is the authority on that entity's name, status, and
metadata. Consumers may declare relationships to the entity, but they do
not redefine it.



**Consequences:**

**Positive:**
- Entity ownership remains unambiguous across repository boundaries
- Consumer references cannot silently override provider truth
- Conflict handling remains deterministic



### DEC-0047: Keep namespace separate from bare ID and use qualification only for cross-repo references

**Rationale:**
Single-repo authoring should remain simple and backward compatible, while
federation requires globally unambiguous identity. Separating namespace from
bare ID preserves local ergonomics while enabling global qualification when
needed.



**Consequences:**

**Positive:**
- Existing local ADR authoring remains valid
- Cross-repo references become explicit and machine-parseable
- Global identity does not require a central ID allocator



### DEC-0077: Emit workspace-attribution-federation.yaml as read-only cross-repo attribution index

**Rationale:**
Per-repo implementation-attribution-evidence.yaml files use bare ADR ids valid
only within each corpus. Workspace reasoning requires a derived federation
artifact keyed by qualified_id (workspaceRepoKey:ADR-L-XXXX) so homonymous
bare ids across repositories are never merged into a single semantic cluster.



**Consequences:**

**Positive:**
- Agents and workspace tools resolve ADR embodiment without bare-id collapse
- Federation remains derived and does not mutate per-repo evidence

**Negative:**
- Workspace manifest repo keys must remain stable for qualified_id namespaces
